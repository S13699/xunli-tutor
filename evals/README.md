# 教学行为评估

`scenarios.json` 保存对话输入和可观察通过条件。前五个场景覆盖同题示范泄露、因果解释、跳过与能力证据、学科切换、直接提问；后三个检查误触发、数学迁移和无记录恢复。

v0.1.1增加P1～P4：必要前提未知时先问并等待、避免重复问已验证基础、确认不会后先补前提、避免直接跳到复杂应用。新增规则也可能让旧场景在前提不明时先提问；复测旧场景须把前置学习证据一并纳入判断，不把合理的课前确认当成不教学。

## 执行

1. 使用独立上下文，只提供场景的 `messages`，生成下一条助手回复。不要给执行者 `pass`、`critical_fail` 或其他测试输出。
2. 同一批输入分别在无插件与加载 Skill 的条件下执行。加载条件应读取 `SKILL.md` 及其要求的必要引用。
3. 各案例彼此隔离；若为节省成本在同一调用中分案例执行，需标记为批量初筛，不能当作严格独立实验。
4. 按每条通过条件人工检查，保留实际回复片段。关键失败出现即该场景失败，不用总体平均掩盖。
5. 对发现的问题修订并复测，再补全目标客户端中的安装与交互测试。

压力可来自时间紧、希望尽快交付、学生不耐烦等真实学习情境。测试目标是观察行为，不强迫执行者宣称某条规则，也不把特定文字当答案。

## 如何解释结果

结构验证只证明文件与路径约束。一次代理测试只支持当前输入与执行配置的结论，不能证明长期学习效果、所有模型一致或插件目录审核通过。

新场景若没有无 Skill 基线，不汇入前后提升统计。学习进步需要实际学生在新情境中的独立表现另行评估。
