# v0.1.1：教学前置知识检查

日期：2026-11-03（Asia/Shanghai）。本次增加生成讲解、示例、推导或练习前的必要前提检查；发现未知或可疑前提，先问并等待回答。规则同时适用于补讲与换例子。

## 旧版基线

独立执行代理读取0.1.0规则后收到P1情境：只学过普通方法与基本类型、没学过接口等内容的学生，请求Comparator教学。实际输出直接开始比较方法和接口解释，并在讲解末尾才给一道判断题：

> 我们用“整数从小到大排序”作例子。先理解比较方法，再学怎样用接口把它交给排序工具；暂时不用 Lambda。

> Comparator就是Java提供的比较规则接口；接口规定要提供什么方法，具体规则由我们实现。

这说明旧版“检查必要前提”的文字没有明确落实为教学前提问并等待；避开Lambda也没有解决接口及比较约定未确认的问题。

## 本次变更

- 入口不再无条件要求指定主题后直接开始，先执行前提检查。
- 核心Skill与通用协议明确先提问、等待回答，不在同一条回复中继续依赖未知前提的教学。
- 检查覆盖示例里顺带引入的语法、术语、符号、工具与调用关系。
- 用户确认不会后先补最小基础或换讲法；待确认点随学习记录交接。
- 已有充分理解证据不重复询问，不把本次要教的目标本身当作必须先会的前提。

## 定向复测范围

P1～P4分别覆盖未知前提前问、已验证基础不重复问、接口前提不会时先补基础、Lambda不会时不跳到Stream。执行者只收到对话输入与Skill位置，没有收到评分条件；使用与旧版测试相同的独立执行代理重新读取新版规则，其上下文保留此前测试任务，因此不属于完全无历史的盲测。

按场景的可观察条件审核，本次4个定向场景均通过：

| 场景 | 实际行为 | 审核 |
|---|---|---|
| P1 | 问接口与实现类关系，到此停下，没有开始Comparator代码 | 通过 |
| P2 | 沿用已验证的函数知识，直接以普通函数解释递归，没有要求先掌握递归 | 通过 |
| P3 | 接口不会时，先问普通方法中类型声明与方法体的区别，不进入Comparator | 通过 |
| P4 | Lambda不会且仅有循环背景时，先问普通方法参数，不进入Stream | 通过 |

P1原文：

> 正式写Comparator会用到接口；你的记录里还没有这项。先确认：你能解释“接口规定要提供哪些方法，实现类给出具体方法内容”这个关系吗？没学过也可以，我们就从这里补起。

P3原文：

> 为避免例子又带入没学过的东西，先确认普通方法中的一个小点：看到`int doubleValue(int x) { return x * 2; }`，你能指出哪部分规定输入、输出类型，哪部分是实际执行的内容吗？

P4原文：

> 讲“把计算传给方法”之前，需要先分清方法接收的参数。你学过普通方法的参数吗？例如`printNumber(3)`里的3，是交给谁使用的？
